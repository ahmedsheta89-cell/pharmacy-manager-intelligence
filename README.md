# Pharmacy Manager Intelligence | ذكاء مدير الصيدلية

تطبيق ويب عربي محلي أولًا يساعد مدير الصيدلية على تحويل ملفات Excel وCSV غير المنتظمة إلى قرارات تنفيذية قابلة للمراجعة. يركز التطبيق على **فهم مصدر البيانات قبل التحليل**، ولا يطبق أي تعيين أو تصحيح للحقول من دون قرار صريح من المدير.

## المبدأ التشغيلي

> تبقى بيانات ملف الاستيراد داخل المتصفح. لا تُرفع ملفات Excel أو عينات الأصناف إلى خدمة خارجية أثناء الاستيراد أو التحرير.

يمر الاستيراد بتسلسل واضح: اختيار المصدر، فحص البنية، مراجعة وتحرير الأعمدة والصفوف محليًا، مقارنة الصفوف الأصلية والمصححة، ثم اعتماد المدير قبل فتح التحليلات.

| المجال | ما يقدمه التطبيق |
| --- | --- |
| تدقيق الاستيراد | كشف العناوين المنزاحة والصفوف غير المنتظمة، مع درجات ثقة وخريطة حقول قابلة للتحرير. |
| تحرير شبيه بـExcel | تعديل العناوين والخلايا والصفوف والأعمدة محليًا، سحب وإفلات، تراجع وإعادة، واختيار نطاقات. |
| ترتيبات المدير | حفظ ترتيبات أعمدة محلية باسم المدير، مع وصف ووسوم لونية وفرع وترتيب مقترح يدوي. |
| تحليلات الصيدلية | المخزون، القرب من الانتهاء، الطلبات المقترحة، الأداء الزمني، ومقارنة الفروع عند توفر البيانات. |
| حماية ونسخ محلي | جلسات محفوظة، نسخ احتياطي اختياري مشفّر، وقفل محلي لإعدادات التقرير. |

## البدء محليًا

### المتطلبات

- Node.js 22 أو أحدث.
- pnpm 9 أو أحدث.

### الأوامر

```bash
pnpm install
pnpm dev
```

لفحص الجاهزية قبل مشاركة أي تغيير:

```bash
pnpm check
pnpm test
pnpm build
```

## بنية المشروع

```text
client/src/components/     واجهة المراجعة ولوحات القرار
client/src/lib/            محركات القراءة والتحليل والتخزين المحلي
client/src/pages/          مسارات التطبيق الرئيسية
server/                    طبقة التشغيل الخاصة بالقالب
scripts/                   تحقق تفاعلي بمتصفح حقيقي
```

## قواعد لا تقبل التنازل

1. **لا تطبيق تلقائي** لأي ترتيب أو تصحيح أو خريطة أعمدة؛ يظل المدير صاحب قرار التطبيق.
2. **لا إظهار للربح أو الهامش** عند غياب بيانات التكلفة الموثوقة من المصدر.
3. **لا حفظ لمحتوى Excel** ضمن ترتيبات المدير أو قوالبه أو سجلات استخدامها؛ تحفظ بيانات تعريفية محلية فقط.
4. **لا تعديل للملف الأصلي**؛ كل التحرير يتم على نسخة معاينة داخل المتصفح.

## جودة التغيير

قبل مشاركة أي تعديل أو فتح طلب سحب، شغّل فحص TypeScript واختبارات Vitest وبناء الإنتاج بالأوامر الموضحة أعلاه. يحفظ المشروع كذلك سيناريو متصفح في `scripts/verify-editable-sheet-undo.mjs` للتحقق من تدفق تحرير الاستيراد الفعلي.

## المساهمة

استخدم فرعًا مستقلًا لكل تحسين، واحرص على تحديث الاختبارات و`todo.md` عند إضافة أي تدفق جديد. قبل فتح طلب سحب، شغّل أوامر التحقق الثلاثة أعلاه، وتأكد من أن أي تغيير في استيراد Excel لا يتجاوز بوابة موافقة المدير.
