# ملاحظات تكامل WhatsApp Business Platform — 25 أغسطس 2026

## متطلبات السياسة

تشترط Meta الحصول على موافقة صريحة مسبقة قبل مراسلة الأشخاص على WhatsApp، مع توضيح اسم النشاط ونوع الاتصال، وتوفير طريقة واضحة لإلغاء الموافقة واحترامها. يمكن جمع الموافقة عبر الموقع أو الرسائل القصيرة أو ورقيًا أو داخل الفرع، بشرط الامتثال للقوانين المحلية.

الرسائل التي يبدأها النشاط خارج نافذة خدمة العميل لمدة 24 ساعة يجب أن تستخدم قالب رسالة معتمدًا. يمكن الرد برسالة غير قالب فقط داخل 24 ساعة من آخر رسالة للعميل.

## مسار التكامل الآمن

1. إنشاء Meta App بحالة WhatsApp وربط حساب WhatsApp Business ورقم عمل مخصص.
2. إنشاء System User وتوليد رمز وصول دائم ذي الصلاحيات المحددة، ثم حفظه كسر خادم فقط.
3. إنشاء قوالب مستقلة: «توافر طلب عميل»، «تذكير مورد»، و«تغيير موعد وصول»، وإرسالها لموافقة Meta.
4. إضافة سجل موافقة العميل أو المورد: التاريخ، القناة، فئة الرسائل، وحالة إلغاء الموافقة.
5. إنشاء خادم Webhook متحقق من التوقيع، يسجل message ID وحالات الإرسال والتسليم والقراءة والفشل بطريقة idempotent لمقاومة تكرار رسائل Meta.
6. يبقى الإرسال في البداية مسودة تحتاج اعتماد المدير أو الموظف، ثم يمكن تفعيل قواعد إرسال ضيقة بعد اختبار القوالب والموافقات.

## لا نفعل

لا نربط WhatsApp الشخصي بالمتصفح، ولا نستخدم مكتبات تحاكي WhatsApp Web أو إرسالًا جماعيًا غير مصرح. لا نرسل رسائل عن منتجات صحية أو أدوية إلا بعد مراجعة سياسات البلد والمتطلبات التنظيمية؛ سياسة WhatsApp تفرض قيودًا إضافية على قطاعات الأدوية والرعاية الصحية، ولا يثبت مسار Cloud API وحده السماح برسائل دوائية في مصر.

> **قرار المرحلة الحالية:** الرقم `01000753375` لا يكفي وحده لبدء التكامل الرسمي. يلزم تأكيد أنه رقم أعمال مخصص، وربطه بحساب Meta Business، ثم إتاحة `phone_number_id` وموافقة المستخدمين وقوالب Meta. إلى ذلك الحين يظل فتح `wa.me` للمراجعة اليدوية فقط.
