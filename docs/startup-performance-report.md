# تقرير تحسين بدء التطبيق والأداء

**التاريخ:** 23 أغسطس 2026  
**النطاق:** بدء شاشة «ذكاء مدير الصيدلية» فقط، مع المحافظة على خصوصية ملفات Excel وصور الفواتير ونتائج OCR الخام داخل المتصفح، وعلى الاعتماد اليدوي للمدير.

## النتيجة التنفيذية

عولج السبب الجوهري للبطء، وهو أن أمر البناء لم يفرض وضع الإنتاج صراحةً؛ لذلك كان يمكن أن يدخل React التطويري كبير الحجم إلى الناتج عند البناء من بيئة تحمل `NODE_ENV=development`. عُدّل أمر البناء ليبني الواجهة والخادم بوضع الإنتاج دائمًا، ثم عُزلت مكتبة Excel ومسارات التصدير والمراجعة والتحليل المتقدم وراء تحميل عند الطلب. لا تُنزّل تلك الوظائف إلا بعد أن يفتحها المدير أو يختار ملفًا أو يطلب تصديرًا.

> **مهم:** تبقى قراءة Excel وOCR وصور الفواتير محلية. التحسين يقلل ما يُحمّل عند فتح التطبيق، ولا يغيّر سياسة الخصوصية أو يضيف أي قرار تلقائي.

| المؤشر | قبل المعالجة | بعد التقسيم الأولي | ناتج الإنتاج النهائي |
|---|---:|---:|---:|
| ملف JavaScript الرئيسي | 2.78 MB | 1.31 MB | **575.24 KB** |
| الحجم المضغوط للملف الرئيسي | 737 KB | 385.14 KB | **169.02 KB** |
| التحسن مقارنة بالبداية | — | 48% أقل تقريبًا | **77% أقل تقريبًا** |
| مكتبة Excel | ضمن مسار الإقلاع | ضمن مسار الإقلاع | **جزء مؤجل مستقل: 143.07 KB gzip** |

تعكس أرقام الحجم ناتج `pnpm build` الإنتاجي. أما القياس المتصفحي أدناه فيستخدم خادم الإنتاج المبني فعليًا، وذاكرة التخزين المؤقت معطلة، وثلاث محاولات مستقلة لكل شاشة.

## التغييرات المنفذة

| المجال | الإجراء المنفذ | الأثر |
|---|---|---|
| وضع البناء | فرض `NODE_ENV=production` في أمر البناء الرسمي | منع تضمين React التطويري في حزمة النشر |
| قارئ Excel | فصل قاعدة اعتماد الأعمدة ومحلل الأرقام ووسوم الحقول عن محرك قراءة الملفات | لا يُحمّل قارئ Excel الكامل لمجرد فتح اللوحة |
| التصدير | تأجيل Excel الخاص بسجل التدقيق وPDF والتصديرات إلى حدث الضغط | نقل تكلفة التصدير إلى وقت طلبه فقط |
| مراكز العمل | إبقاء مراكز المراجعة والمخزون والتدفق والفواتير وغرفة العمليات والتقارير خلف `lazy` و`Suspense` | تجعل الشاشة الرئيسية أخف وأسرع في الاستجابة |
| حزمة الإنتاج | إنشاء جزء مستقل لمكتبة `xlsx` | لا يدخل في الموارد الأولية للوحة الرئيسية |
| تقديم الإنتاج | إصلاح مسار أصول `dist/public` في الخادم المجمع | أثبتت استجابة نسخة الإنتاج الفعلية بـHTTP 200 |
| المراقبة | إضافة `pnpm analyze:bundle` و`pnpm measure:startup` | قياس قابل للتكرار لأي تعديل لاحق |

## التحقق

نجح فحص TypeScript، ونجحت **55 حالة Vitest** في 19 ملف اختبار. كما نجح سيناريو المتصفح الفعلي على سطح المكتب والهاتف بملف الصيدلية، وشمل الاستيراد، تحرير الشيت والتراجع، اعتماد الخريطة، غرفة العمليات، وحالة الفواتير الفارغة. استُخدم كذلك خادم إنتاج مبني مستقل للتحقق من تقديم الصفحة وقياسها.

## تشغيل القياس مستقبلًا

نفّذ الأوامر التالية من جذر المشروع:

```bash
pnpm analyze:bundle
pnpm build
pnpm measure:startup
```

لقياس ناتج الإنتاج الحقيقي، شغّل خادم الإنتاج على منفذ متاح ثم مرر رابطه عبر `PERF_BASE_URL`، مثل:

```bash
PERF_BASE_URL=http://127.0.0.1:3101/ pnpm measure:startup
```

## حدود واعية

ظلّت تبعية SheetJS مؤجلة ومعزولة خلف حواجز `spreadsheetSafety`، إذ لا توجد نسخة مصححة متاحة في السجل المعتمد حاليًا؛ لم يُدّعَ حل ثغرة لا تتوفر لها ترقية. كما لم تُرقَّ Recharts من الإصدار 2 في هذا العمل، لأن ذلك تغيير توافق منفصل يحتاج اختبار واجهات الرسوم أولًا.
