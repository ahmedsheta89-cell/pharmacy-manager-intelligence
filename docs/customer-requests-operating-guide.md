# دليل تشغيل طلبات العملاء وفواتير الموردين

## مبدأ التشغيل

تعتمد الدورة على **مراجعة ثم اعتماد**. لا تحفظ المنصة صور الفواتير أو نصوص OCR الخام، ولا تخصم احتياجًا أو تغيّر حالة طلب عميل أو ترسل رسالة WhatsApp تلقائيًا. تقتصر قاعدة البيانات على قرار التوريد المعتمد وبنوده وكمياته، وطلبات العملاء وسجل الأحداث اللازم للتشغيل.

| المرحلة | المسؤول | الإجراء | الضابط |
|---|---|---|---|
| طلب العميل | فريق طلبات العملاء أو المدير | تسجيل العميل والهاتف والصنف والكمية | منع طلب مفتوح مكرر للعميل والصنف |
| قراءة الفاتورة | المدير | رفع الصورة محليًا ومراجعة OCR أو إدخال البنود يدويًا | لا تخزين للصورة أو OCR الخام |
| اعتماد التوريد | المدير | اعتماد بنود الفاتورة والكميات بعد المراجعة | لا تخصيص تلقائي لطلبات العملاء |
| إتاحة الصنف | المدير | اختيار بند فاتورة معتمد وكمية مناسبة ثم اعتماد التخصيص | يجب أن يطابق الصنف بالكود أو الاسم، ولا تتجاوز الكمية المتاح |
| التواصل | فريق الطلبات أو المدير | فتح رسالة WhatsApp الجاهزة ومراجعتها وإرسالها يدويًا | يُسجَّل فتح الرسالة ولا ترسل المنصة أي رسالة تلقائيًا |
| الإغلاق | فريق الطلبات أو المدير | تأكيد التسليم أو الإلغاء مع سبب | يبقى سجل زمني لكل تغيير جوهري |

## صلاحيات فريق طلبات العملاء

يتلقى الزميل رمز انضمام أحادي الاستخدام لمدة 24 ساعة من المدير بعد تسجيل دخوله. يمنحه الرمز دور `customer_requests` الذي يستطيع الوصول فقط إلى قائمة طلبات العملاء: إنشاء طلب، الاطلاع على حالته، فتح رسالة WhatsApp عند الجاهزية، تأكيد التسليم، أو الإلغاء بسبب واضح.

> لا يمنح هذا الدور أي وصول إلى ملفات Excel أو معاينة المصدر أو صور الفواتير أو OCR أو اعتماد الموردين أو تنبيهات المخزون أو غرفة العمليات أو الحوكمة.

## استخدام عملي مختصر

يفتح المدير «فواتير الموردين»، يراجع محتوى الفاتورة ويعتمد قرار التوريد. بعدها يفتح «طلبات العملاء»، ويظهر له اقتراح مطابق فقط عندما يكون هناك بند توريد معتمد، ثم يختار كمية ويعتمد الإتاحة. عند اكتمال كمية العميل تصبح الحالة «جاهز للتواصل». يفتح موظف الطلبات WhatsApp، يراجع الرسالة ويرسلها بنفسه، ثم يؤكد التسليم لاحقًا.

## ملاحظات الخصوصية

يحفظ النظام اسم العميل ورقم هاتفه وطلبه لغرض التواصل التشغيلي فقط. يحتفظ سجل التدقيق بمن قام بإنشاء الطلب أو تخصيص التوريد أو تغيير الحالة، من دون تضمين صور الفواتير أو نصوص OCR الخام في السجل الدائم.

## المتابعة السريعة وقوالب الرسائل

تتيح شاشة طلبات العملاء البحث الفوري باسم العميل أو رقم الهاتف أو اسم الصنف أو كوده، مع تصفية مستقلة لكل حالة. تظل بطاقات الرأس شاملة لجميع الطلبات، بينما تعرض القائمة النتيجة المطابقة فقط حتى لا يُفهم التصفية على أنها حذف للبيانات.

تعرض لوحة المدير زمن الاستجابة الفعلي: الطلبات المفتوحة، الطلبات التي تجاوزت 24 ساعة، ومتوسط الوقت من إنشاء الطلب إلى إتاحته، ومن الإتاحة إلى تسجيل التواصل. لا يظهر رقم مصطنع عندما لا توجد عمليات مكتملة؛ تظهر علامة عدم التوفر بدلًا منه.

يدير المدير قوالب WhatsApp من داخل مساحة العمل، ويمكنه تحديد قالب افتراضي أو أرشفة قالب أو تعيينه متاحًا لفريق الطلبات. المتغيرات المدعومة هي `{{customerName}}` و`{{productName}}` و`{{productCode}}` و`{{requestedQuantity}}`. يختار الموظف قالبًا معتمدًا، ثم تفتحه المنصة في WhatsApp ليُراجَع ويُرسل يدويًا فقط.

## الدخول والحفظ والأكواد والتوريد المنتظر

لا يظهر نموذج طلب العميل للحساب غير المسجل. بدلاً من ذلك تظهر بوابة دخول واضحة؛ بعد تسجيل الدخول يختار المستخدم مساحة العمل أو ينشئها صراحةً إن لم تكن موجودة. يمنع ذلك ظهور رسالة `Please login (10001)` بعد إدخال الطلب؛ لا يُستدعى أي إجراء حفظ محمي قبل تحقق الجلسة.

يعين المدير كودًا فريدًا لكل عضو داخل مساحة الصيدلية، مثل `EMP-01`. الكود يقبل الحروف الإنجليزية والأرقام والشرطة فقط، ويُرفض تكراره داخل المساحة. يعرض تقرير الأداء الفعلي خلال 7 أو 30 أو 90 يومًا عدد الطلبات التي سجلها الموظف، والتواصل، والتسليم، ومتوسط الدقائق من جاهزية الصنف إلى تسجيل التواصل؛ لا تنشأ بيانات أداء تخمينية عند غياب الأحداث.

تسجل قائمة انتظار الموردين الاسم وموعد الوصول المتوقع والملاحظة وحالة يغيرها المدير يدويًا: «مجدول»، «وصل»، «متأخر»، أو «ملغي». لا تغير هذه الحالة مخزونًا أو فاتورة أو طلب عميل؛ يظل اعتماد التوريد من الفاتورة إجراءً منفصلًا بقرار المدير.

## بوابتا المدير والموظف ودورة الرسائل

بعد الدخول، يوجَّه عضو فريق طلبات العملاء الذي يملك هذا الدور فقط إلى **بوابة الموظف**. تعرض له تسجيل الطلبات والبحث والمتابعة ورسالة WhatsApp عند الجاهزية والتسليم؛ ولا تظهر له شاشة Excel أو الفواتير أو اعتماد التوريد أو الأداء أو مواعيد الموردين أو إعدادات القوالب. أما المالك والمدير فيدخلان **بوابة المدير** التي تجمع لوحة الاستجابة وأكواد الموظفين ووصول الموردين وقرارات التوريد وقوالب الرسائل.

| الحالة | من يقررها | الإجراء التالي |
|---|---|---|
| مطلوب | موظف أو مدير عند التسجيل | ينتظر مراجعة المدير أو قرار بدء الطلب |
| جاري الطلب / توريد جزئي | المدير فقط | يمكن فتح رسالة تحديث للعميل للمراجعة اليدوية |
| تم التوفير · جاهز للتواصل | المدير بعد تخصيص بند فاتورة معتمد | يظهر للموظف زر رسالة التوافر وفتح WhatsApp |
| تم التواصل | الموظف أو المدير | يتابع التسليم أو الإغلاق بسبب |
| تم التسليم | الموظف أو المدير | يغلق الطلب كسجل مكتمل |
| غير متوفر | المدير فقط مع سبب إلزامي | يفتح نموذج رسالة اعتذار للمراجعة ولا يرسلها تلقائيًا |
| ملغي | الموظف أو المدير مع سبب | إغلاق تشغيلي مستقل عن قرار عدم التوفر |

> تظل صيغ «جاري الطلب» و«تم التوفير» و«غير متوفر» قابلة للتعديل من المدير. اختيارها أو فتحها لا يرسل رسالة من النظام؛ يفتح WhatsApp للمراجعة والإرسال البشري فقط إلى أن يجهز التكامل الرسمي المعتمد.
