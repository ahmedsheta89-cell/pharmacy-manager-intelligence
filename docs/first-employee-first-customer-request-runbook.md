# دليل أول موظف وأول طلب عميل

## الغرض

يختبر هذا الدليل دورة العمل الحقيقية من دون مخاطرة ببيانات عميل فعلي: دخول المدير، انضمام موظف، تعيين كود الموظف، حفظ طلب عميل، ثم اختبار التوريد والتواصل. استخدم رقمك الشخصي أو رقم اختبار أولًا.

## الجزء الأول: إعداد كود أول موظف

| الخطوة | ينفذها | الإجراء المتوقع |
|---|---|---|
| 1 | المدير | افتح الرابط الثابت للتطبيق ثم اضغط «تسجيل الدخول الآمن». |
| 2 | المدير | اختر مساحة الصيدلية. إن لم تظهر مساحة، اضغط «تجهيز مساحة العمل» مرة واحدة وانتظر تأكيد النجاح. |
| 3 | المدير | افتح «طلبات العملاء» ثم «إدارة وصول الفريق». أنشئ رمز انضمام لفريق الطلبات وانسخه للموظف. |
| 4 | الموظف | يسجل الموظف دخوله بحسابه ثم يفتح «طلبات العملاء» ويدخل رمز الانضمام لمرة واحدة. |
| 5 | المدير | من لوحة «أكواد الموظفين»، عيّن كودًا واضحًا مثل `EMP-001`. يحظر النظام تكراره داخل مساحة الصيدلية. |
| 6 | المدير | تأكد أن اسم الموظف وكوده ظاهران في لوحة الفريق؛ لا تمنحه صلاحية فواتير أو Excel أو حوكمة. |

## الجزء الثاني: اختبار حفظ أول طلب

1. سجّل دخول الموظف، واختر نفس مساحة الصيدلية.
2. من شاشة «تسجيل طلب عميل»، اكتب بيانات اختبارية: اسم مثل «اختبار تشغيل»، رقم WhatsApp تملكه، اسم صنف واضح، كود الصنف إن وجد، وكمية 1. لا يجب أن تظهر في هذه الشاشة قائمة طلبات أو تفاصيل إدارية.
3. اضغط «حفظ طلب العميل» مرة واحدة، ثم انتظر رسالة النجاح. يجب أن يظهر الطلب للمدير بحالة **مطلوب** ومسجلاً باسم الموظف. عند تسجيل المدير بالنيابة عن زميل، يختار المدير الاسم من القائمة المخصصة قبل الحفظ.
4. افتح الطلب في حساب المدير للتأكد أن الفريق يراه ضمن نفس مساحة العمل فقط.

> إذا ظهر زر «تسجيل الدخول الآمن» بدل النموذج، فهذا صحيح: سجل الدخول أولًا. وإذا ظهر «تجهيز مساحة العمل»، نفّذه مرة واحدة ثم أعد فتح الشاشة. لا تحاول الحفظ عندما تكون رسالة `Please login (10001)` ظاهرة.

## الجزء الثالث: اختبار دورة التوريد والتواصل

1. من حساب المدير، افتح «فواتير الموردين» وأدخل بندًا تجريبيًا يطابق اسم أو كود الصنف في طلب العميل.
2. راجع الكمية ثم اعتمد التوريد يدويًا. لا يتم تحديث العميل تلقائيًا.
3. افتح «طلبات العملاء»، واختر تخصيص كمية التوريد المعتمدة لهذا الطلب، ثم اعتمد الإتاحة.
4. ستصبح الحالة **جاهز للتواصل**. يختار الموظف قالب WhatsApp المعتمد ويفتحه لمراجعته وإرساله يدويًا.
5. بعد تواصل فعلي، يسجل الموظف الحالة المناسبة، ثم يؤكد التسليم أو الإلغاء بسبب واضح.

## معايير النجاح

| الاختبار | النتيجة الصحيحة |
|---|---|
| حفظ الطلب | يظهر فورًا بحالة «مطلوب» بلا خطأ 10001 |
| صلاحية الموظف | يستطيع إنشاء وتحديث طلبه فقط، ولا يرى Excel أو الفواتير أو تقارير الإدارة |
| اعتماد التوريد | لا يغير الطلب إلا بعد اعتماد المدير وتخصيص كمية واضح |
| WhatsApp الحالي | يفتح رسالة للمراجعة، ولا يرسلها تلقائيًا |

لإجراء اختبار قبول كامل بحساب مدير وحساب زميل، اتبع `docs/customer-requests-acceptance-checklist.md` وسجل النتيجة لكل خطوة قبل استخدام بيانات عميل حقيقية.

## قبل تفعيل WhatsApp الرسمي

يظل زر WhatsApp الحالي هو المسار الآمن للتجربة. لا تبدأ الإرسال الآلي قبل إنشاء موافقة صريحة للعميل أو المورد وسجل إلغاء موافقة وقوالب معتمدة؛ راجع `docs/whatsapp-integration-notes.md`.
